# dddd（叮叮当当）｜第一个 MVP 设计

面向电脑和手机浏览器的单人像素风拼刀原型，采用第一人称动力甲头盔视角，背景暂时套用战锤 40K。

**穿着动力甲，与一个兽人反复拼刀，验证这件事是否足够爽。**

本文只描述第一个 MVP 的设计，内容为待实现方案，数值为初始调试参考。

## 项目脚手架

使用 **Phaser 4.2.1 + Vite + TypeScript**。当前只包含启动占位场景、180×320 竖屏等比缩放和开发构建配置；战斗、左右操作、血条、架势和音效尚未实现。

推荐 Node.js 24（最低 22.12.0）。在项目目录运行：

```sh
npm install
npm run dev
```

打开终端输出的本地地址。手机与电脑连接同一局域网时，可打开终端输出的 Network 地址查看同一竖屏画面。电脑宽窗口中画面居中、两侧留白。

```sh
npm run check    # TypeScript 类型检查
npm run build    # 类型检查并构建到 dist/
npm run preview  # 本地预览构建产物，需先运行 build
```

主要文件：

| 文件 | 用途 |
|---|---|
| `src/main.ts` | 创建 Phaser 实例与处理入口热更新 |
| `src/game/config.ts` | 画布尺寸、像素显示与竖屏缩放配置 |
| `src/game/scenes/MainScene.ts` | 启动占位场景，后续开发入口 |
| `src/style.css` | 页面尺寸、手机安全区域与画布样式 |
| `vite.config.ts` | 开发服务器与构建配置 |

下文为待实现的 MVP 设计。

## 目标与范围

第一个 MVP 对应开发路线中的“拼刀手感原型”。核心目标是验证读招、拼刀、抓破绽攻击和处决的手感。

| 项目 | MVP 设计 |
|---|---|
| 平台 | 电脑、手机浏览器 |
| 模式 | 单人 |
| 场景 | 一个可反复练习的近身战斗场景 |
| 敌人 | 一个兽人，用刀光、枪口火光和爆炸提示表现 |
| 画面 | 统一竖屏布局，电脑与手机显示相同的战斗画面 |
| 操作 | 战斗区域左半边**闪**、右半边**砍**，电脑与手机规则一致 |
| 威胁 | 刀砍、近身开枪、爆炸 |
| 战斗系统 | 拼刀、格挡、闪避、玩家血条、敌人架势、破绽、处决 |
| 视听反馈 | 顿帧、火花、震屏、合成音效 |
| 调试 | 判定窗口叠加层，招式数据修改后立即生效 |

## 核心战斗循环

1. 敌人出招，显示对应的视觉和声音提示。
2. 玩家根据威胁按“砍”或“闪”，把握应对时机。
3. 成功拼刀增加敌人架势；格挡挡住刀砍但不增加敌人架势；被击中扣血。
4. 敌人连招结束，出现“破绽”，玩家按“砍”增加敌人架势。
5. 敌人架势崩溃，出现处决红点，玩家按“砍”处决，结束战斗。
6. 战斗结束后可重新开始，反复体验并调整参数。

## 操作

电脑浏览器和手机采用相同的竖屏战斗画面与左右半屏操作规则。“砍”和“闪”的具体动作由当前威胁与战斗状态决定。

| 战斗区域 | 动作 | 电脑浏览器 | 手机 |
|---|---|---|---|
| 左半边 | **闪** | 鼠标点击 | 触屏点击 |
| 右半边 | **砍** | 鼠标点击 | 触屏点击 |

左右区域以实际显示的竖屏战斗画面为准；电脑窗口两侧的留白不属于战斗操作区域。

### 威胁与应对

| 威胁 | 出招提示 | 按“砍” | 按“闪” |
|---|---|---|---|
| 刀砍 | 武器寒光一闪，随后出现刀光轨迹 | 完美窗口内拼刀；稍差时格挡；错过窗口则被砍中 | 侧闪 |
| 近身开枪 | 枪口闪光，瞄准线收缩 | 时机准确时用刀弹开子弹 | 侧闪躲开 |
| 爆炸 | 地面出现红色范围 | 无法防住爆炸，被炸中 | 后撤，跳出范围 |

### “砍”的状态规则

- 敌人出现处决红点时，按“砍”执行处决。
- 敌人处于破绽期间，按“砍”进行攻击，增加敌人架势。
- 敌人刀砍或近身开枪时，按“砍”尝试相应的防御动作。
- 没有合法攻击机会或防御窗口时乱按“砍”，会产生约 300 毫秒收招硬直，期间可能挨刀。

### “闪”的定位

闪避用于保命，不增加敌人架势，也不提供反击收益。玩家可以用闪避降低应对压力，但需要通过拼刀和破绽攻击推进战斗。

闪避的有效时机、持续时间及是否有冷却尚待调试确定。

## 拼刀、格挡与受击

| 结果 | 战斗影响 | 反馈 |
|---|---|---|
| 完美拼刀 | 敌人架势上涨，玩家不扣血 | 清脆的“铛”、火花、顿帧、震屏 |
| 格挡 | 挡住刀砍，玩家不扣血，也不增加敌人架势 | 与完美拼刀可区分的反馈，具体强度待调 |
| 被击中 | 扣除玩家血量 | 明确的受击提示，具体表现待调 |

近身子弹可通过准确按“砍”弹开；非完美时机是否允许格挡，以及弹开子弹对敌人架势的影响，尚待明确。

敌人一套连招结束后进入硬直，屏幕显示“破绽”。玩家在此期间攻击；破绽之外乱砍，会撞上敌人的下一招。

## 玩家血条、敌人架势与处决

- 玩家只有**血条**，不设架势条。
- 敌人只有**架势条**，不设生命值或血条。
- 拼刀和破绽攻击增加敌人架势；格挡只防住刀砍，不增加敌人架势。
- 敌人架势随时间缓慢回落，需要持续施压。
- 敌人架势满后崩溃，出现红点，按“砍”处决并获胜。
- 玩家血量耗尽时战斗失败；处决敌人时战斗胜利，结束后可重新开始。

## 敌人设计

MVP 只使用一个兽人，不展开完整 Boss 阶段设计。

- **视觉：** 粗重、暗红带锈的刀光，明显的枪口火光。
- **声音：** 粗重的武器声。
- **节奏：** 刀砍前摇清晰，便于反复练习拼刀；连招结束后留出攻击间隔。
- **招式：** 刀砍、近身开枪、爆炸三种基础威胁。
- **呈现：** 不画敌人本体和肖像，主要通过攻击特效体现存在感。

## 画面与音效

### 头盔视角

- 电脑浏览器和手机统一使用竖屏布局，保持相同的画面比例、界面位置和左右操作分区。
- 使用低分辨率竖屏画布，例如 180×320，通过 `image-rendering: pixelated` 等比放大，适配可用显示区域。
- 电脑宽窗口中将竖屏战斗画面居中，两侧留白；手机也保持竖屏比例。
- 用简化的动力甲面罩边框、扫描线和数据读数表现头盔视角。
- 界面显示玩家血条、敌人架势条、破绽提示和处决红点。
- 攻击提示必须清晰，装饰效果不能遮挡判定信息。

### 程序生成特效

| 内容 | 做法 |
|---|---|
| 刀光 | 记录挥动轨迹点，绘制渐隐像素弧线与拖尾 |
| 出招寒光 | 闪一个亮点，随后出现蓄力轨迹线 |
| 火花 | 带速度、重力和寿命的粒子，从刀光交点溅出 |
| 弹道 | 带拖尾的亮线 |
| 爆炸 | 圆形扩散，颜色由白到黄、红、黑，叠加碎片粒子 |
| 震屏 | 画面整体快速抖动几下 |
| 顿帧 | 拼刀成功时短暂冻结画面 |

拼刀手感优先打磨**顿帧、火花和震屏**。

### 音效

- 用 Web Audio 合成拼刀的“铛”声。
- 拼刀越准，声音越清脆，形成准确度反馈。
- 枪口提示配上膛声，帮助玩家识别近身射击。

## 初始参数与调试

| 参数 | 初始参考值 |
|---|---|
| 刀砍前摇：提示出现到攻击落下 | 400～800 毫秒 |
| 完美拼刀窗口 | 约 120 毫秒 |
| 格挡窗口 | 约 250 毫秒 |
| 窗口外乱按“砍”的收招硬直 | 约 300 毫秒 |
| 顿帧 | 60～100 毫秒 |

调试叠加层需要显示出招时间、判定窗口与输入结果，帮助区分按早、按晚和成功拼刀。招式数据修改后立即生效，便于连续试手感。

除上述数值外，玩家受击伤害、敌人架势增减、敌人架势恢复速度、破绽时长与闪避参数也需要可调。窗口在攻击落点前后的分布及完美窗口与格挡窗口的包含关系，尚待明确。

## 制作方式

- 优先用代码生成刀光、火花、弹道、爆炸、震屏与顿帧。
- 音效使用 Web Audio 合成。
- 如需静态头盔界面素材，可使用 [Aseprite](https://www.aseprite.org/)。
- 如程序生成的爆炸不满意，可使用 [Pixel FX Designer](https://codemanu.itch.io/pixelfx-designer) 生成逐帧精灵图。
- 使用外部动画资源时，导出 PNG 精灵图与 JSON 帧数据，由游戏读取播放。
- 背景专有名词保存在数据文件中，便于配置替换。

## 实现顺序与完成标准

1. 建立统一的低分辨率竖屏头盔画面，实现电脑鼠标与手机触屏的左侧“闪”、右侧“砍”输入。
2. 实现一个兽人的刀砍，以及拼刀、格挡、受击和乱按硬直。
3. 接入玩家血条、敌人架势、破绽攻击和处决，形成可重复的完整战斗。
4. 加入近身开枪与爆炸，验证两个按键对三种威胁的应对。
5. 打磨顿帧、火花、震屏和音效，使用调试叠加层反复调参。

**核心完成标准：对着一个兽人反复拼刀，自己觉得爽。**

具体验收时检查：

- 电脑浏览器和手机的竖屏画面、界面布局与操作规则一致：左侧“闪”，右侧“砍”。
- 两种设备都能完成一场战斗并重新开始。
- 三种威胁提示可辨识，按键结果符合对应规则。
- 完美拼刀、格挡与受击的反馈可区分。
- 破绽攻击、敌人架势崩溃与处决流程可完整体验。
- 调整招式数据后可立即验证手感变化。
